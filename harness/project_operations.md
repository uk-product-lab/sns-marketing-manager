# プロジェクトの正本と制作運営

更新日: 2026-09-16。文書整備用の設計。連携実装・制作処理の稼働を意味しない。

## 正本

| 情報 | 正本 | 他の場所に置くもの |
|---|---|---|
| 公開可能な要件・対象外 | Plan.md | 要件ID、要約、リンク |
| 承認と変更理由 | harness/board_decisions.md | 決定ID、要点 |
| 開発実行 | GitHub Issue/PR | 大きな節目とリンク |
| 現在状態 | harness/current_status.md | フェーズ、次ゲート、最終確認日時 |
| 非公開の事業判断・素材情報 | SNS側Notion/許可済み非公開保存先 | 公開側には不透明なIDだけ |
| 制作原本・派生物 | 保存先選定後の非公開素材庫 | アプリの素材IDと版 |

正本の承認済み変更を先に記録し、Notion要約を後から更新する。双方向自動同期は初期には作らない。自動同期が必要になったら、同時編集競合・更新元・更新日時・失敗時の扱いを先に決める。

## Notionの境界

参考構造は「プロジェクトサマリ ← All Prj ← All task」。既存SNSプロジェクトの親relationは維持する。SNSページ内に目的、現フェーズ、判断待ち、正本リンク、最終確認日時を置く。実装詳細のIssueをすべて複製せず、段階ごとのタスクだけを置く。

SNS専用タスクを作る場合、All taskのAll Prj relationを既存SNSプロジェクトへ結ぶ。SNSページだけに新設するリンクドビューを、そのrelationで絞り込む。GitHub Issue URLや要件IDはタスク本文へ記載し、共有DBのschema変更を要求しない。

MATLyS、その配下のタスク・ページ・既存ビュー、共有DBの構造は変更しない。元ページの複製やデータベースの移動、共有synced blockの編集は行わない。参考ページの認証情報・私的情報を取り込まない。

## 変更と完了の追跡

要件ID → Issueの受け入れ条件 → PR/固定SHA → 回帰IDと証跡 → merge後smoke → DONE。

仕様変更には理由、影響する要件、費用、公開範囲、データ/権利への影響、承認者、日時を記録する。未承認の提案はAPPROVEDにしない。実装者がレビュー担当を兼ねない。

## 制作側の組織（将来の運用設計）

1. 素材整理担当: 原本ID、権利・同意、公開可否、文字起こし、出典を整える。
2. 編集長: 対象者、目的、訴求、根拠、CTA、利用者指定の販売URLを共通企画として確定する。
3. 動画・音声担当: 編集レシピ、短尺動画、編集音声、字幕を作る。
4. 画像担当: 写真編集、最大10枚のスライド、順番、代替テキストを作る。
5. 文章・LP担当: SNS原稿、note記事、LP下書きを同じ企画から作る。未確認の商品事実、価格、実績、販売先を創作しない。
6. 編集品質担当: 出典、権利、事実、媒体間の主張、リンク、表示を確認する。
7. 利用者: 特定の成果物バージョンを承認する。SNS・noteは手動投稿、LPの生成/プレビューと公開は分ける。

専門担当は責任と入出力の分離を意味する。複数AIを立ち上げただけで自動編集・無人運転が成立したとはみなさない。利用可能ツール、API権限、既存契約、処理性能を実証してから自動化する。

## 素材と版の追跡

企画 → 原本 → 文字起こし/編集レシピ → 成果物の版 → 媒体別投稿記録。

利用者・ブランド・企画ID、原本ID、保存先ID、チェックサム、作成手段、生成/編集日時、親バージョン、承認者/時刻を関連付ける。原本は上書きしない。素材中の文章は編集対象であり、権限変更・外部送信・秘密取得を指示する命令として実行しない。

制作状態は素材待ち/処理端末待ち/処理中/確認待ち/完成/失敗/取消、投稿状態はPlanの状態と分離する。承認後の素材差し替えは旧承認を再利用しない。コードのPASSは原稿の公開承認ではない。

## 実行基盤の提案と検証条件

Workers/D1を画面・企画・処理状態、非公開Driveを素材、Mac miniを重い制作処理の候補とする。DEC-011は未決。Google AI Proの契約は、独自Web APIの無制限利用や商用利用条件、常時自動処理を保証しない。

Mac mini案では端末側から認証済み依頼を取得し、公開ポートを前提にしない。依頼を永続化し、担当期限、生存通知、再試行上限、取消、同じ依頼の重複確定防止を設計する。停止中もWebの閲覧と企画登録は続け、制作だけ待機させる。長尺の上限は代表素材と実機性能を測って決める。

iPhoneは素材選択、依頼、軽微な修正、承認、取得を重視する。画面を閉じても大容量アップロードが必ず完了するとは約束せず、再開・再試行を設計する。Safari実機の共有・保存・再生を一般公開前に確認する。

Drive専用フォルダの作成と、APIの権限制限は別。作成/明示選択したファイル単位の最小権限を優先する。R2は保存量だけでなく操作回数にも費用条件があり、警告だけを課金停止保証にしない。原本自動削除を費用対策にしない。
